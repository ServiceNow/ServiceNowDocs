# Configuring Unified Secrets Gateway

Learn how to configure Unified Secrets Gateway \(USG\) to organize and control access to secrets on your instance.

## Roles required for configuring Unified Secrets Gateway

To learn about the roles required to configure USG, see [Role requirements for Unified Secrets Gateway](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/platform-security/usg-roles.md).

-   **[Role requirements for Unified Secrets Gateway](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/platform-security/usg-roles.md)**  
Learn about the roles required to configure Unified Secrets Gateway \(USG\).
-   **[Create an alias group](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/platform-security/usg-create-alias-group.md)**  
Create an alias group to organize secrets and define where they are stored in ServiceNow.
-   **[Create an identity group](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/platform-security/usg-create-identity-group.md)**  
Create a custom identity group to manage access for a specific set of members.
-   **[Create consumer grants](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/platform-security/usg-create-consumer-grants.md)**  
Create consumer grants to specify which identity groups can access which alias groups.
-   **[Add members to an identity group](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/platform-security/usg-add-members-identity-group.md)**  
Add existing members to an identity group to control which entities can access secrets through consumer grants.
