# Monitoring application performance

Track the health and performance of your organization's applications, devices, networks, and communication tools from the Service Operations Workspace. Use metric rules to detect deviations, and review agent policy coverage and system compliance to keep monitoring accurate across your fleet.

Digital End-User Experience \(DEX\) provides proactive visibility into your organization's end-user experience and helps you diagnose issues. You do this work from the Service Operations Workspace, using features such as application and user navigation and trend analysis to identify the root cause of an issue. For information about opening the workspace, see [Open DEX Application and Device Health](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/open-dex-workspace.md). For an overview of the landing page you see when you open it, including the Employee experience overview section and the devices world map, see [Landing page](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/dex-workspace-dashboard-tab.md).

## What you can monitor

The DEX Workspace lets you monitor across these areas:

-   **System performance**

    Track CPU, memory, disk, and I/O metrics to prevent application bottlenecks and verify resource availability. See [Monitor system performance](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/monitor-system-performance.md).

-   **User applications and network**

    Monitor an app's network from a selected device to spot issues early, review connection details, and inspect app connection stability, connection path, and live hops. See [Monitor your user apps network](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/monitor-user-apps-network.md).

-   **Installed and web application metrics**

    View CPU and memory usage for installed applications and metrics such as users, sessions, response time, page load time, and availability for web applications. See [View metrics of an installed application](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/view-installed-app-metrics.md) and [View metrics of a web application](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/view-web-app-metrics.md).

-   **Application identity information**

    Look up the URLs for the applications DEX tracks. See [View the domain or URL for a web application](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/view-app-url.md).

-   **Device Action Library**

    From a selected device, view the services and actions available for that device in the Digital End-User Experience Action Library. See [View actions in the Digital End-User Experience Action Library](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/view-actions-in-actions-library.md).

-   **Agent policies and system compliance**

    Review the agent policies used during check runs on associated CIs, and check whether devices adhere to your organization's application and policy compliance rules. See [View agent policies](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/view-agent-policies.md) and [View system compliance](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/view-device-compliance.md).

-   **Communication tools**

    Monitor Microsoft Configuration Manager \(MCM\) client health, Microsoft Teams call quality, Zoom call quality, and Zoom room performance. See [MCM monitoring overview](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/mcm-monitoring-overview.md), [Microsoft Teams call quality monitoring overview](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/microsoft-teams-call-quality-monitoring-overview.md), [Zoom call quality monitoring overview](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/zoom-call-quality-monitoring-overview.md), and [View Zoom room metrics](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/view-zoom-room-metrics.md).


## Metric rules and alerts

Metric rules set the criteria and thresholds that trigger alerts when performance metrics deviate from expected values. A set of preconfigured metric rules is available with the base system, but they remain inactive on installation. For details about how metric rules surface in the monitoring workflow, see [Using alert rules for Digital End-User Experience](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/metric-rules.md).

## Custom insights reports

Build custom reports on any performance metric collected on a device or application, filter by department, device list, or operating system, and save the report for repeat analysis. See [Create an insights report](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-service-management/digital-end-user-experience-dex/create-insights-report.md).
