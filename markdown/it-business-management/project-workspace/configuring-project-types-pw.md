# Configuring project types in Project Workspace

Configure project types so that each type of project in Project Workspace has its own custom fields, form view, and visible modules.

A project type combines a dynamic category, a form view, and module visibility settings. For an overview of these components, see [Project types in Project Workspace](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-business-management/project-workspace/project-types-in-pw.md).

To configure a project type, complete the following tasks:

-   **Create a dynamic category \(optional\)**

    A default dynamic category is available in the base system, so a custom dynamic category isn't required to create a project type. Create one only when projects of a type require custom fields that the default category doesn't provide. See [Create a dynamic category for a project type](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-business-management/project-workspace/create-dynamic-category-pw.md).

-   **Create a project type**

    Create the project type and define its form view, dynamic category, and visible modules. See [Configure project type fields and layouts](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-business-management/project-workspace/configure-project-type-pw.md).


-   **[Create a dynamic category for a project type](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-business-management/project-workspace/create-dynamic-category-pw.md)**  
Create a dynamic category to define the custom fields that appear on project records of a specific project type in Project Workspace.
-   **[Configure project type fields and layouts](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/it-business-management/project-workspace/configure-project-type-pw.md)**  
Define custom fields, a unique form layout, and the visible modules to support configuration independence across different types of projects.
