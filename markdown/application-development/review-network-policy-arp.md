# Review network policies

Review automatically created network policy records and change their status as needed based on intended application behavior.

## Before you begin

-   For network policies to be automatically generated, Application Runtime Policy \(ARP\) must be enabled in either Tracking or Enforcing mode for the application you're developing.
-   If ARP is in Enforcing mode, you must review and approve the generated network policies before the application can access the specified resource. For more information about Tracking and Enforcing modes, see [Application Runtime Policy modes](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/application-development/arp-modes.md).

Role required: arp\_admin or admin.

## About this task

**Note:** All policy records generated by ARP must be in the **Allowed** or **Denied** state before publishing to the Application Repository or the ServiceNow Store. Policies left in the **Requested** state block publication.

## Procedure

1.  Navigate to **All** &gt; **System Policy** &gt; **Application Runtime Policy** &gt; **Network Policies**.

2.  From the list, locate a policy record with the **Requested** status and review the policy details.

    Policies with the **Allowed** or **Denied** status can also be reviewed and changed as needed.

3.  Change details of the policy record, such as the **Short Description**, if needed.

    1.  Double-click the value in the column you want to change \(or use the keyboard shortcut\).

    2.  Enter the updated value.

    3.  Select the Save \(Enter\) icon\[Omitted image "releaseops-save-enter-icon.png"\] or use the Enter key to save your selection.

    \[Omitted image "arp-short-desc-xmp.gif"\] Alt text:

    **Warning:** Changing automatically generated policy details other than the short description could block necessary resource access. Test application functionality again after making any changes to policy record details.

4.  Double-click the value in the **Status** field \(or use the keyboard shortcut\) to open the drop-down list of status options.

5.  Select an option to allow or block resource access as defined in the policy.

    -   Select **Allowed** to enable access.
    -   Select **Denied** to block access.
6.  Select the Save \(Enter\) icon\[Omitted image "releaseops-save-enter-icon.png"\] or use the Enter key to save your selection.

7.  Repeat for each **Requested** policy record.


## Result

Network policies with the **Allowed** state permit the application to connect to the specified network resource. When you reload the application page, any features that rely on the specified network resources function as programmed.

Network policies with the **Denied** state prevent the application from connecting to the specified network resource. To prevent errors, make sure the application doesn't continue attempting to access the blocked resources.
