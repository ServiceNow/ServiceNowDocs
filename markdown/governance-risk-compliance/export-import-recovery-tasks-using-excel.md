# Export and import recovery tasks from Microsoft Excel

Export recovery task records to a Microsoft Excel file, edit the data offline, and import the updated file to create or update many recovery tasks at once.

## Before you begin

You need view access to the records referenced in the import file, such as configuration items, users, assignment groups, recovery strategies, loss scenarios, and related plans.

Role required: sn\_bcm.core\_viewer

## About this task

The **Export to Excel** and **Import from Excel** actions are available in the **Recovery tasks** related list on a business continuity plan. Use this procedure to create or update many recovery tasks in a single edit.

## Procedure

1.  Navigate to **Workspaces** &gt; **Business Continuity Workspace** and open the business continuity plan.

2.  On the plan record, select the **Recovery tasks** tab.

3.  In the action bar, select **Export to Excel**.

    The **Export Excel** dialog opens with a **File name** field. The default name is the plan short description followed by "- recovery task". You can change it to any name that identifies the export.

    \[Omitted image "export-recovery-tasks-excel-dialog.png"\] Alt text: Export Excel dialog with the File name field and Download button on the Recovery tasks tab.

4.  Select **Download**.

    The Microsoft Excel file downloads to your machine.

5.  Open the downloaded file and edit the recovery tasks in the **Recovery task** sheet.

    Observe the following constraints when you edit the file:

    -   Edit only the unlocked cells. Locked cells are read-only fields, and any edit to them is ignored at import time.
    -   Use the provided drop-down lists. The **Owner** field uses a user drop-down list.
    -   The **Additional assignees** field accepts comma-separated user names. Microsoft Excel validates each entry against the list of existing users while you edit the file. If you bypass this validation \(for example, by unprotecting the sheet\) and enter a user name that doesn't exist, the import doesn't return an error. That name is silently skipped and the assignment isn't set for that entry. Review the Import log to confirm that all assignees are resolved as expected.
    -   The **Dependencies** field accepts comma-separated task IDs.
    -   To update an existing task, keep its numeric task ID. To add a task, enter a temporary N-prefixed identifier, for example, `N1`, in an empty row. The system assigns the task a real task ID after import, and you can reference the N-prefixed identifier in the **Dependencies** column of any row in the file.
    -   Don't rename sheets, rearrange columns, or change the file format. Save the file as ".xlsx".
    For the full set of column rules, including fields that are mutually exclusive or hidden on the form, see [Importing and exporting recovery tasks from Microsoft Excel](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/zurich/markdown/zurich/governance-risk-compliance/using-export-import-feature-recovery-tasks.md).

6.  Save the Microsoft Excel file after you complete your edits.

7.  On the **Recovery tasks** related list, select **Import from Excel**.

    The **Import Recovery Tasks** dialog opens where you can attach the file.

    **Note:** Use the file generated by **Export to Excel**. Don't upload a manually created spreadsheet.

8.  Attach your saved Microsoft Excel file and select **Save**.

    The import is queued. The staged rows are processed in batches of 500 by a scheduled job that runs every 60 seconds. A row with an existing task ID updates that task. A row with a temporary N-prefixed task ID creates a task and is assigned a real task ID.


## What to do next

To check the results of an import, select **View import progress** in the plan header to reopen the progress tracker. You can also review the plan's **Import log** tab for warnings and errors. The **Transform history** tab provides a summary of the import run, including rows that were inserted, updated, or skipped.

If a row fails during import, correct it and import the file again:

1.  On the **Recovery task** sheet, unlock the sheet by using **Review** &gt; **Unprotect Sheet**.
2.  Delete the rows that were processed successfully, keeping only the rows that you need to import again.
3.  Save the file, and repeat the last two steps of this procedure to import it again.
