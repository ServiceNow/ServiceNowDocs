# New state fields

Fields used in the activities of the New state in an issue's lifecycle.

The fields available in the New state depend on the playbook associated with the issue's workflow. The following activities and fields are examples from the default issue workflow playbook.

## Issue details

Describe the issue in clear, simple terms so that stakeholders can understand what happened.

|Field|Description|
|-----|-----------|
|**Number**|The issue record number. Read-only.|
|**Name**|A name for the issue.|
|**Description**|A description of the issue.|
|**Issue source**|How the issue originated, such as Ad-Hoc. Read-only.|

## Ownership and stakeholders

Assign responsibility for managing and resolving the issue.

|Field|Description|
|-----|-----------|
|**Assigned to**|The user responsible for the issue.|
|**Assignment group**|The group responsible for the issue.|
|**Issue manager**|The user managing the issue.|
|**Issue manager group**|The group managing the issue.|
|**Executive owner**|The executive accountable for the issue.|
|**Created by**|The user who created the issue. Read-only.|

## Due date

Specify when the issue must be resolved.

|Field|Description|
|-----|-----------|
|**Due date**|The date by which the issue must be resolved.|

## Data access and confidentiality

Control access to the issue based on organizational requirements.

|Field|Description|
|-----|-----------|
|**Functional domain**|The functional area associated with the issue, such as IT Risk, Compliance, or Privacy.|
