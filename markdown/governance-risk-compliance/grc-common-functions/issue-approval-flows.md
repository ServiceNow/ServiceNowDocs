# Issue approval flows

Manage approvals for issue and remediation task state changes and due date extensions.

An issue workflow can add an approval checkpoint before an issue or remediation task moves past a specific state, or before its due date is extended.

## Key benefits

-   Add oversight before a state change or due date extension takes effect.
-   Track approval requests, decisions, and history directly on the associated record.
-   Enable more than one approver to review a single request.

## Approval types

|Approval type|Description|
|-------------|-----------|
|**State Change**|Requires approval before an issue or remediation task can move past a specific state.|
|**Due Date Extension**|Requires approval before an issue or remediation task's due date can be extended.|

Approvals are defined as part of an issue workflow. See [Configure approvals for a workflow](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/australia/markdown/governance-risk-compliance/grc-common-functions/configure-approvals-for-a-workflow.md).

-   **[Request an approval](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/australia/markdown/governance-risk-compliance/grc-common-functions/request-an-approval.md)**  
Request approval for a state change or a due date extension on an issue or remediation task.
-   **[Cancel an approval](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/australia/markdown/governance-risk-compliance/grc-common-functions/cancel-an-approval.md)**  
Cancel a pending approval request on an issue or remediation task.
-   **[Review and respond to an approval request](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/australia/markdown/governance-risk-compliance/grc-common-functions/review-and-respond-to-an-approval-request.md)**  
Review a pending approval request and approve or reject it.
