# Flow troubleshooting agent

Diagnose and resolve flow errors from a conversation. Resume a flow the point of error, analyze flow steps, identify conflicts with business logic, and receive targeted recommendations to troubleshoot your flows.

When a flow fails or produces unexpected results, troubleshooting the root cause can be time-consuming and require deep knowledge. You can use the flow troubleshooting agent to shorten this process to review a flow directly from a conversation.

This intelligent agent analyzes flow execution data, identifies potential conflicts with business rules or other workflows, and recommends specific actions to resolve errors.

## Benefits

-   **Summarize flow steps:** Understand the purpose and sequence of steps in your failed flow.
-   **Analyze data in motion:** Review the data used and generated by each flow step to identify transformation errors or missing data.
-   **Identify conflicts:** Detect potential conflicts with other business logic, workflows, or system configurations that may be causing failures.
-   **Receive actionable recommendations:** Get specific, evidence-based actions you can take to resolve the error and resume your flow.
-   **Review evidence and reasoning:** View the analysis and recommendations with supporting data and evidence so you understand the reasoning behind each suggestion.

## Capabilities

The Flow Troubleshooting Agent provides the following capabilities to help you diagnose and resolve flow execution errors:

|Capability|Description|
|----------|-----------|
|Flow step summarization|The agent analyzes your flow and provides a clear summary of each step's purpose, inputs, outputs, and role in the overall flow logic.|
|Data analysis and tracing|The agent reviews the data used and generated by your flow, including data transformations, field mappings, and value changes across steps. Identifies data validation errors, missing values, or type mismatches.|
|Conflict detection|The agent scans for and identifies potential conflicts with other business logic, workflows, business rules, field-level security, and integration configurations that may be causing your flow to fail.|
|Evidence-based recommendations|The agent provides specific, actionable recommendations to resolve your flow error, with supporting evidence and reasoning for each suggestion.|
|Conversational interface|The agent provides a conversation interface for you to interact with it naturally through conversation. Ask follow-up questions, dive deeper into specific steps, or explore alternative solutions without leaving the troubleshooting interface.|
|KB article recommendations|The agent provides links to support KB articles to help you diagnosis and troubleshoot instance issues.|

## When to Use

Use the Flow Troubleshooting Agent when:

-   A flow execution fails and you want to understand why.
-   You want to analyze flow data to diagnose root causes.
-   You suspect a conflict between your flow and other business rules or integrations.
-   You need conversational debugging help without digging through logs manually.

For a list of verified scenarios where you can use the Flow Troubleshooting Agent, see [Flow troubleshooting scenarios](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/build-workflows/workflow-studio/flow-troubleshooting-scenarios.md).

## How to Access the Flow Troubleshooting Agent

For the Brazil release, an administrator must create a system property called com.glide.hub.flow.launch\_troubleshooting\_agent. For more information about creating the system property, see [Create troubleshooting agent system property](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/build-workflows/workflow-studio/create-troubleshooting-agent-system-property.md).

You can launch the Flow Troubleshooting Agent from multiple locations in ServiceNow:

-   From the flow execution details view, select the **Troubleshoot** button.
-   From a related record, select the **ServiceNow Otto** button \(the conversational AI assistant\) to access the agent.
-   From any screen, select the **ServiceNow Otto** button \(the conversational AI assistant\) to access the agent.

## Prerequisites

To use the Flow Troubleshooting Agent, you must have:

-   The com.glide.hub.flow.launch\_troubleshooting\_agent system property set to true.
-   The sn\_troubleshoot.flow\_troubleshooting\_agent\_user role to run the Flow Troubleshooting Agent.
-   The flow\_designer or flow\_admin role to access flow execution details
-   The ServiceNow Otto panel enabled in your instance. For setup instructions, see [Overview tab in AI Admin Hub](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/intelligent-experiences/configuring-now-assist.md).
-   The Webcrawler external content connector \[com.sn\_ext\_conn\_wc\] plugin to enable searching for support KB articles. For more information, see [Webcrawler external content connector](https://raw.githubusercontent.com/ServiceNow/ServiceNowDocs/brazil/markdown/platform-administration/webcrawler-external-content-connector.md).
-   The KB Troubleshooting Agent: ServiceNow Support Crawl scheduled script execution to gather support KB articles.
